## Authentication

The API uses two types of authentication tokens (JWTs), passed in the `Authorization: Bearer <token>` header:
- **Diner Tokens**: Short-lived session tokens generated by scanning a QR code on a table. Used for the ordering flow.
- **Staff Tokens**: Standard Supabase Auth tokens for employees, managers, and owners.

### `POST /api/auth/session`
Initiates a new dining session.
- **Body:** `{ restaurantId: UUID, branchId: UUID, tableId: UUID }`
- **Response:** `{ ok: true, data: { sessionId, sessionToken, dinerToken } }`

### `POST /api/auth/staff`
Login for staff members.
- **Body:** `{ email, password }`
- **Response:** `{ ok: true, data: { user, token } }`

## Diner Endpoints (Requires Diner Token)

### `GET /api/restaurants/:id/menu/categories`
Returns all active menu categories for the restaurant.

### `GET /api/restaurants/:id/menu/items`
Returns all active menu items with their modifiers and prices.

### `GET /api/cart`
Returns the current session's cart and items.

### `POST /api/cart/items`
Adds an item to the cart.
- **Body:** `{ menuItemId: UUID, quantity: number, modifiers: Array }`

### `PATCH /api/cart/items/:id`
Updates the quantity or modifiers of a cart item.

### `DELETE /api/cart/items/:id`
Removes an item from the cart.

### `POST /api/orders`
Places an order for all items currently in the cart.
- **Body:** `{ specialInstructions?: string }`

## Staff Endpoints (Requires Staff Token)

### `GET /api/kitchen/orders`
**Roles:** `kitchen`, `branch_manager`, `owner`
Returns all active orders for the staff member's branch.

### `PATCH /api/orders/:id/status`
**Roles:** `kitchen`, `branch_manager`, `owner`
Updates the overall status of an order.
- **Body:** `{ status: 'pending' | 'preparing' | 'ready' | 'served' | 'cancelled' }`

### `POST /api/kitchen/items/:id/complete`
**Roles:** `kitchen`, `branch_manager`, `owner`
Marks an individual order line item as completed (ready to serve).

## Analytics Endpoints (Requires Owner or Branch Manager Token)

### `GET /api/analytics/sales`
**Query Params:** `from` (ISO date), `to` (ISO date), `branchId` (optional)
Returns revenue, top items, and category breakdown.

### `GET /api/analytics/kitchen-timing`
Returns prep time deltas and heatmap analytics for kitchen efficiency.

### `GET /api/analytics/upsell`
**Roles:** `owner`
Returns the effectiveness and acceptance rates of AI upsell triggers.

### `GET /api/analytics/menu-performance`
**Roles:** `owner`
Returns menu item conversion metrics and 3D viewing lift data.

## WebSocket & Realtime

Menuva uses Supabase Realtime channels to push instant updates.
1. **Diners** subscribe to `session:<session-id>` to receive `cart_updated`, `order_status_changed`, and `payment_requested` events.
2. **Kitchen Staff** subscribe to `kitchen:<branch-id>` to instantly see `new_order` and `order_updated` events.
